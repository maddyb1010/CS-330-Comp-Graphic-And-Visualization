# CS 330: Computational Graphics and Visualization

## How do I approach designing software?

For this project, I wanted to keep the scene fairly simple while still making it recognizable as a fortune-teller's table. I focused more on the crystal ball, patterned tablecloth, and tarot cards because those were some of the most noticeable parts of my reference image. I kept other details, like the candleholders, more basic rather than trying to recreate every part of them.

Some of my design decisions also changed once I could see everything together. For example, the tarot cards originally had plain blue backs, but I felt like they looked unfinished compared to the rest of the scene. I ended up adding gold borders and diamond patterns, which made them look much better. In future projects, I think I would spend a little more time planning the layout and deciding which details are worth focusing on before getting too far into development.

## How do I approach developing programs?

Throughout this course, I got more experience working with existing code and modifying it as I added new features. One thing I found useful was creating reusable functions for objects like the candles and tarot cards. Instead of writing nearly identical code for each card, I could use the same function with different positions. This also made it easier to change their appearance later.

There was definitely some trial and error involved. At one point, the tarot cards were partially underneath the crystal ball's stand, so I had to adjust their coordinates to move them forward. I also made changes to the camera controls and tested the perspective and orthographic views to make sure they worked correctly. Each milestone added something new, including textures, lighting, and camera movement. Earlier in the course, I was mainly focused on getting individual parts to work, but toward the end, I was paying more attention to how everything looked and functioned together.

## How can computer science help me in reaching my goals?

I hadn't really worked with 3D graphics before this course, so using OpenGL was a different experience from some of my other programming assignments. I got more practice with C++ and learned more about how objects, textures, lighting, and camera controls work together. While I might not use computational graphics directly in my remaining courses, the experience I gained with debugging, organizing code, and working through a larger project will still be useful.

I'm interested in pursuing a career in software testing or quality assurance, so I think the testing side of this project was especially relevant. There were times when the program ran without errors, but something in the scene still wasn't quite right. I had to figure out what was causing the issue, make changes, and test it again to see if the problem was resolved. That is something I can see applying to software testing professionally, where a program working without errors doesn't necessarily mean everything is functioning as intended.
